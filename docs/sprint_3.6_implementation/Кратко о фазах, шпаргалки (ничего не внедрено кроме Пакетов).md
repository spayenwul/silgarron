Это детерминированный, послойный процесс процедурной генерации сложного биологического мира. Каждый этап использует результаты предыдущих, добавляя новый слой данных. Детерминизм достигается за счет хеширования исходного `seed` для каждой отдельной фазы, что гарантирует воспроизводимость мира при одном и том же `seed`.

**Ключевое изменение в версии 3.0:** Порядок генерации Скелета и Сосудистой сети изменен. Теперь **Скелет (Phase 2) генерируется до Сосудов (Phase 3)**. Это позволяет артериям реалистично "огибать" плотные костные структуры, что является критическим улучшением логики мира. Также добавлена новая фаза **Гидравлической Эрозии (Phase 4.5)** для создания более реалистичных ландшафтов.

### Phase 0: Инициализация и Meta-параметры

*   **Цель:** Заложить фундамент для всей генерации, установив глобальные, неизменные параметры мира.
*   **Как это будет сделано:**
    1.  **Чтение конфигурации:** Загружаются основные параметры мира из YAML-файла: `world_phase` (глобальное состояние, например "EXHALE" - выдох, что влияет на базовую температуру), `world_age` (возраст мира) и `map_size` (глобальный размер карты, 512x512).
    2.  **Детерминизм:** Создается специальная hash-функция (`_hash_seed`). Она принимает базовый `seed` мира (например, "silgarron_alpha_01") и суффикс (например, "continent" или "spine"). Это позволяет генерировать уникальный, но постоянный `int` seed для каждого модуля генерации.
    3.  **Создание объекта World:** Все эти параметры инкапсулируются в основной объект `World`, который будет передаваться и дополняться на последующих этапах.

### Phase 1a: Создание «Позвоночника» (Spine Creation)

*   **Цель:** Сгенерировать центральную, органическую ось мира, которая будет служить основой для скелета и континента.
*   **Как это будет сделано:**
    1.  **Базовая линия:** Создается вертикальный массив точек с севера на юг.
    2.  **Искривление:** К X-координатам этих точек применяется 1D-шум Перлина. Это превращает прямую линию в плавную, естественно изогнутую кривую.
    3.  **Сглаживание:** Полученный "сырой" путь сглаживается с помощью B-spline интерполяции для устранения резких углов.
    4.  **Поле Влияния:** Вокруг финального пути позвоночника создается "маска влияния" (`spine_influence_mask`) — 2D-карта, где значение максимально на самом позвоночнике и плавно затухает до нуля с расстоянием. Эта маска будет использована для "притягивания" суши к позвоночнику.

---

### Phase 1b: Формирование Континента (Continent Growth)

*   **Цель:** Создать основную массу суши, ее рельеф и разместить на ней ключевые "органы".
*   **Как это будет сделано:**
    1.  **Базовый рельеф:** Генерируется 2D-карта высот (`heightmap`) с помощью шума Перлина с низкой частотой для создания плавных холмов и долин.
    2.  **Привязка к позвоночнику (опционально):** Карта высот умножается на маску влияния из Phase 1a. Это "поднимает" рельеф вокруг позвоночника, делая формирование континента вдоль него более вероятным.
    3.  **Формирование суши:** Применяется порог `sea_level`. Все значения на карте высот выше этого порога становятся сушей, ниже — океаном.
    4.  **Очистка береговой линии:** К полученной маске суши применяются морфологические операции (`binary_opening` для удаления мелких "островов" и `binary_closing` для заполнения мелких "заливов"), а затем сглаживание по Гауссу для более плавной береговой линии.
    5.  **Анализ геометрии:** Рассчитывается центр масс континента и его главная ось (направление наибольшей протяженности) с помощью метода главных компонент (PCA).
    6.  **Размещение органов:** В ключевых точках, определенных геометрией (центр масс, вдоль главной оси), размещаются метаданные "органов" (Метаболический центр, Желудок, Нервные узлы).

### Phase 2: Генерация Скелета (Skeleton Generation) [⚠️ v3.0]

*   **Цель:** Создать костную структуру мира, которая определяет основной рельеф и служит препятствием для сосудов.
*   **Как это будет сделано:**
    1.  **Позвонки:** Вдоль пути позвоночника (из Phase 1a) с равным интервалом размещаются "позвонки" (`vertebrae`) — точки с высоким значением плотности кости и бонусом к высоте.
    2.  **Рёбра:** От позвонков генерируются рёберные дуги с помощью L-систем. Это позволяет создавать сложные, ветвящиеся костные структуры, похожие на настоящие рёбра.
    3.  **Фаланги:** В определенных регионах (например, "конечности") размещаются костные структуры, имитирующие пальцы.
    4.  **Карта плотности костей (`bone_density_map`):** **Это ключевой результат фазы.** Создается 2D-карта, где значение от 0 до 1 отражает плотность костной ткани. Позвонки имеют плотность 1.0, рёбра — 0.7 и т.д. Эта карта будет использоваться в Phase 3 для прокладки маршрутов сосудов.
    5.  **Финальный рельеф:** Итоговая карта высот (`elevation`) композируется из нескольких слоев: основной вклад вносят костные структуры (60%), добавляется небольшой региональный уклон (20%) и текстурный шум Перлина (20%).

### Phase 3: Генерация Сосудистой Сети (Vessel Network) [⚠️ v3.0]

*   **Цель:** Создать сеть артерий и лимфатических сосудов, соединяющих органы и избегающих костей.
*   **Как это будет сделано:**
    1.  **Точки притяжения:** Вокруг органов создаются "точки притяжения" (`attraction points`).
    2.  **Алгоритм колонизации пространства (Space Colonization):** Начиная от "Метаболического ядра", сеть сосудов итеративно растет в сторону ближайших точек притяжения.
    3.  **Pathfinding с учетом плотности:** **Ключевое нововведение.** При поиске пути стоимость маршрута рассчитывается как `дистанция * (1 + плотность_кости * штраф)`. Это заставляет алгоритм прокладывать пути в обход зон с высокой плотностью на `bone_density_map`, то есть артерии будут "огибать" кости.
    4.  **Типизация:** Сосуды классифицируются на артериальные (от центра к органам) и лимфатические.
    5.  **Точки выхода (`vein_outlets`):** Определяются места, где артерии подходят близко к поверхности в низинах. Эти точки станут источниками рек в следующей фазе.

---

### Phase 4.5: Гидравлическая Эрозия (Hydraulic Erosion) [🆕 v3.0]

*   **Цель:** Создать реалистичные речные долины и каньоны, симулируя эрозию от потоков жидкости.
*   **Как это будет сделано:**
    1.  **Предварительное сглаживание:** Карта высот от Phase 2 сглаживается по Гауссу, чтобы убрать артефакты от L-систем (рёбер).
    2.  **Фокусированные источники воды:** Создается карта водных источников. В точках `vein_outlets` (из Phase 3) задаются очень мощные источники, а по всей остальной карте — слабый "фоновый дождь".
    3.  **Итеративная симуляция:** Запускается симуляция эрозии на N итераций. На каждой итерации:
        *   Рассчитывается, как вода течет вниз по склонам (алгоритм D8).
        *   Там, где поток воды сильный, высота ландшафта уменьшается (происходит эрозия).
        *   **Защита костей:** Эрозия происходит в 3 раза медленнее в областях с высокой плотностью костей (`bone_density_map > 0.5`).
    4.  **Результат:** Получается новая, эродированная карта высот с глубокими речными долинами, начинающимися от `vein_outlets`.

### Phase 4: Гидрология (Hydrology)

*   **Цель:** Сгенерировать полноценную речную сеть на основе эродированного ландшафта.
*   **Как это будет сделано:**
    1.  **Источники:** В качестве основных источников рек используются `vein_outlets` (из Phase 3), а также добавляются случайные "природные источники" в высокогорных районах.
    2.  **Направление потока (D8):** Для каждой клетки карты определяется, в какую из 8 соседних клеток будет стекать вода (в ту, что находится ниже всех).
    3.  **Накопление потока (Flow Accumulation):** Начиная с источников, симулируется, как вода течет вниз по карте направлений. В каждой клетке суммируется весь объем воды, который в нее втекает.
    4.  **Маска рек:** Создается маска рек (`river_mask`) путем применения порога к карте накопления. Клетки, где накопленный поток превышает `river_threshold`, становятся частью реки.

---

### Phase 5: Климат (Climate)

*   **Цель:** Рассчитать карты температуры и влажности на основе всех предыдущих слоев.
*   **Как это будет сделано:**
    1.  **Базовая температура:** Устанавливается в зависимости от глобальной фазы мира (`EXHALE` = тепло, `INHALE` = холодно).
    2.  **Температурные модификаторы:**
        *   **Органы:** Горячие органы (Метаболическое ядро) создают вокруг себя ореолы тепла.
        *   **Кости:** Плотные костные структуры излучают тепло и "охлаждают" окружающие ткани.
        *   **Артерии:** Сосуды с горячей лимфой локально повышают температуру.
        *   **Высота:** Температура понижается с увеличением высоты.
    3.  **Влажность:**
        *   **Реки:** Создают зоны высокой влажности вдоль своего течения, которая экспоненциально спадает с расстоянием.
        *   **Биоактивные зоны:** Некоторые органы (например, Метаболическое ядро) выделяют споры, повышая локальную влажность.
        *   **Высота:** Высокогорные районы более сухие.
    4.  **Нормализация:** Финальные карты температуры и влажности приводятся к диапазону.

### Phase 6: Дыхательная Система (Respiration System)

*   **Цель:** Создать сеть "альвеолярных каверн", которые являются источником биоактивных газов.
*   **Как это будет сделано:**
    1.  **Карта потенциала:** Рассчитывается `respiratory_potential` — карта вероятности появления каверн. Потенциал выше в местах с плотными костями, рядом с позвоночником и в "грудном" регионе (THORAX).
    2.  **Размещение каверн:** Используется взвешенная выборка Пуассоновского диска для размещения каверн. Этот алгоритм расставляет точки случайным образом, но не ближе заданного минимального расстояния друг к другу, причем плотность точек зависит от карты потенциала.
    3.  **Классификация:** Каверны классифицируются по причине их формирования (рядом с позвонком, у ребра, в полости кости или аномальные).
    4.  **Симуляция выдоха:** С помощью алгоритма поиска в ширину (BFS) от каждой каверны распространяется "биоактивное насыщение", которое постепенно затухает с расстоянием. Это создает карту `bioactive_saturation`.

### Phase 7: Ткани (Tissues / Biome Assignment)

*   **Цель:** Финальный этап, на котором каждой клетке мира назначается определенный тип "ткани" (биома) на основе всех собранных данных.
*   **Как это будет сделано:**
    1.  **Сбор контекста:** Для каждой клетки собирается полный набор из ~11 параметров: высота, температура, влажность, плотность кости, биоактивное насыщение, близость к реке, органу, сосуду, регион и т.д.
    2.  **Иерархическое применение правил:** Назначение ткани происходит по системе приоритетов:
        *   **Приоритет 1 (Спецслучаи):** Клетки, являющиеся частью каверны, артерии или реки, сразу получают свой тип ткани (`alveolar_cavern`, `arterial_canal`).
        *   **Приоритет 2 (Органы):** Для клеток вблизи определенных органов применяются уникальные правила (например, "кислотные озера" у "желудка").
        *   **Приоритет 3 (Регионы):** Применяются правила, специфичные для крупных регионов (например, "хитиновые пластины" в "грудной клетке").
        *   **Приоритет 4 (Стандартные правила):** Если ни одно из вышестоящих правил не сработало, применяется обширный набор стандартных правил из файла `tissue_rules.yaml`, который сопоставляет диапазоны параметров (температура, влажность и т.д.) с типами тканей.
    3.  **Финальная карта:** Результатом является `tissue_map` — 2D-массив, где каждая клетка содержит строковый ID назначенной ей ткани.

### 1. Анализ пробелов и полноты системы

Система обладает высокой степенью полноты, и большинство ключевых аспектов учтены. Однако есть несколько моментов, которые либо являются "узкими местами", либо представляют собой скрытую сложность, не до конца раскрытую в плане.

#### **Пробелы и потенциальные проблемы:**

1.  **Обработка крайних случаев в Phase 1b (Continent Growth):**
    *   **Пробел:** План не описывает, что произойдет, если после морфологических операций (`binary_opening`) не останется суши, или если континент разделится на несколько крупных, несвязанных частей. Текущий алгоритм подразумевает единый континент, так как рассчитывается один `center_of_mass` и одна `major_axis`.
    *   **Рекомендация:** Следует добавить шаг проверки после морфологических операций. Например, выбрать самый большой "остров" в качестве основного континента или, в случае неудачи, перезапустить генерацию континента с другим (производным) seed.

2.  **Алгоритм стока воды в Phase 4 (Hydrology) и 4.5 (Erosion):**
    *   **Пробел:** План упоминает алгоритм D8, но не затрагивает критическую проблему "стоков" или "раковин" (`sinks`) — это клетки или области, которые ниже всех своих соседей. В такой точке вода скапливается и "исчезает" из симуляции, обрывая течение рек.
    *   **Рекомендация:** Необходимо добавить обязательный подшаг **"Заполнение стоков" (`fill sinks`)** перед расчетом направления потока. Это стандартная процедура в гидрологическом моделировании, которая искусственно "поднимает" уровень таких ям до уровня их самой низкой точки выхода, обеспечивая непрерывность речной сети.

3.  **Переходные зоны в Phase 7 (Tissues):**
    *   **Пробел:** Система правил присваивает каждой клетке один конкретный тип ткани. Это может привести к резким, неестественным границам между биомами (например, "кислотное озеро" может напрямую граничить с "хитиновой пластиной").
    *   **Рекомендация:** Логично было бы добавить финальный пост-процессинговый шаг — **"Сглаживание границ биомов"**. Это может быть реализовано через клеточный автомат или фильтр, который создает "переходные" ткани на границах двух резко отличающихся зон.

### 2. Места, требующие разбиения на подшаги

Некоторые шаги в плане описаны концептуально, но их реализация потребует значительного количества подзадач.

1.  **`_generate_ribs_lsystem` (Phase 2):**
    *   **Текущее состояние:** Упомянуто "TODO: Полная реализация L-Systems с turtle graphics".
    *   **Требуемые подшаги:**
        1.  Реализация парсера для правил L-системы (Axiom, Rules).
        2.  Создание "черепашьей" графики, которая интерпретирует символы (`F`, `+`, `-`, `[`, `]`) как команды (двигаться вперед, повернуть, сохранить/восстановить состояние).
        3.  Логика "столкновения" и адаптации: что делать, если ребро "упирается" в другой орган или кость? Оно должно остановиться или изогнуться?
        4.  Конвертация пути "черепахи" в набор сегментов или в растровую маску для `bone_density_map`.

2.  **`_generate_vessel_network_density_aware` (Phase 3):**
    *   **Текущее состояние:** Описан итеративный алгоритм колонизации пространства.
    *   **Требуемые подшаги:**
        1.  **Оптимизация поиска:** Поиск ближайшего "кончика" (`tip`) для каждой точки притяжения на каждой итерации — это операция сложностью O(N*M). Для ускорения необходимо использовать пространственные структуры данных, такие как **KD-дерево** или сетка, для быстрого поиска соседей.
        2.  **Обработка завершения:** Что делать, если алгоритм завершился по `max_iterations`, но не все органы "подключены"? Нужен механизм для форсированного соединения оставшихся точек или отчет об ошибке.
        3.  **Формирование иерархии:** После генерации сети сегментов, полезно будет преобразовать ее в древовидную структуру для более простого анализа потоков и вычисления толщины сосудов (более толстые у основания, тонкие на концах).

3.  **`_assign_tissue_cell` (Phase 7):**
    *   **Текущее состояние:** Описан алгоритм сбора контекста и применения правил для одной клетки.
    *   **Требуемые подшаги (оптимизация):**
        1.  **Векторизация контекста:** Вместо итерации по каждой клетке и вызова `_build_cell_context` 512x512 раз, следует предварительно рассчитать все карты контекста (например, `distance_to_vessel_map` через `distance_transform_edt`) для всей карты.
        2.  **Применение правил через маски NumPy:** Вместо цикла по клеткам, можно применять правила сразу ко всей карте, используя логические маски NumPy. Например: `mask = (temp > 0.8) & (moisture < 0.2)`. Это ускорит выполнение в сотни раз.

### 3. Где наиболее логично учитывать "взаимовлияние"?

Взаимовлияние — это самая сильная сторона этой системы. Вот как оно уже реализовано и где его можно усилить:

#### **Уже существующее (однонаправленное) влияние:**

*   **Spine → Continent (Phase 1a → 1b):** Позвоночник формирует "хребет", вдоль которого растет континент. **Это отлично.**
*   **Skeleton → Elevation (Phase 2):** Кости напрямую формируют основной рельеф. **Это ключевая связь.**
*   **Skeleton → Vessels (Phase 2 → 3):** Плотность костей создает "штрафную" карту для прокладки маршрутов сосудов. **Это главное улучшение v3.0.**
*   **Vessels → Hydrology (Phase 3 → 4 & 4.5):** Выходы артерий становятся источниками эрозии и рек. **Прекрасная логическая связка.**
*   **Skeleton → Erosion (Phase 2 → 4.5):** Кости защищены от эрозии. **Еще один отличный пример взаимовлияния.**
*   **Все предыдущие фазы → Tissues (Phase 0-6 → 7):** Финальная фаза является кульминацией, собирая все слои данных для принятия решения. **Логичное завершение.**

#### **Места для усиления взаимовлияния (двунаправленные или более сложные связи):**

1.  **Обратное влияние Эрозии на Рельеф (Phase 4.5 → Phase 2):**
    *   **Идея:** Сейчас эрозия создает финальную карту высот. Но в реальном мире эрозия может *обнажать* твердые породы. Можно было бы создать **цикл обратной связи**: после нескольких итераций эрозии, те места, которые эродировали очень медленно (из-за защиты костей), могли бы получить *увеличение* `bone_density` (имитация обнажения твердых костных пород). Это сделало бы ландшафт еще более драматичным.
    *   **Где реализовать:** Внутри итеративного цикла `_hydraulic_erosion_focused`.

2.  **Влияние Климата на Эрозию (Phase 5 → Phase 4.5):**
    *   **Идея:** Сейчас эрозия использует универсальную карту "дождя". Но климат генерируется позже. Можно поменять порядок или создать **предварительную, упрощенную карту климата**. Тогда в зонах с высокой влажностью (`moisture`) фоновый дождь и, следовательно, эрозия были бы сильнее.
    *   **Где реализовать:** Потребуется либо перенести часть генерации климата перед эрозией, либо создать "предварительную" карту влажности.

3.  **Влияние Тканей на параметры (Phase 7 → Финальные карты):**
    *   **Идея:** Сейчас ткани — это финальный результат. Но они могли бы оказывать обратное влияние. Например, после присвоения биома `acid_lake`, можно было бы локально *понизить* `elevation` в этой зоне и *повысить* `moisture` до 1.0, чтобы параметры соответствовали биому. Биом `thermal_vents` мог бы локально повышать `temperature`.
    *   **Где реализовать:** В качестве пост-процессингового шага после `_generate_tissue_map`. Это сделало бы мир более самосогласованным.

### Рабочий пакет 1: Основа мира (Макро-структура)

Этот пакет отвечает за создание базовой формы мира — его контуров, оси и ключевых точек.

*   **Состав:**
    *   Phase 0: Seed и Meta-параметры
    *   Phase 1a: Spine Creation
    *   Phase 1b: Continent Growth & Organ Placement

*   **Цель:** Получить детерминированную базовую 2D-форму континента, его центральную ось и расположение "органов". Это фундамент, на котором будет строиться всё остальное.

*   **Выходной артефакт:**
    1.  **Визуализация:** Чёрно-белое изображение 512x512 с маской континента. На него можно наложить линию "позвоночника" (spine), центр масс и главную ось.
    2.  **Данные:** Объект `ContinentData`, содержащий маску суши, карту высот, координаты центра, оси и органов.

*   **Критерии валидации:**

    *   **Функциональная валидация (Unit-тесты):**
        *   `_hash_seed` должен возвращать одинаковый `int` для одинаковых `seed` и `suffix`.
        *   Конфигурационный YAML-файл успешно загружается, параметры соответствуют ожидаемым.
        *   Размеры всех генерируемых массивов (маска, карта высот) строго 512x512.
        *   Функция PCA корректно находит главную ось на тестовом наборе точек.

    *   **Визуальная валидация:**
        *   Континент представляет собой единую крупную массу суши (а не россыпь мелких островов).
        *   Береговая линия выглядит естественно — не слишком "рваная" и не слишком гладкая.
        *   "Позвоночник" (spine) — это плавная кривая, идущая с севера на юг примерно по центру карты.
        *   Если включен режим `spine_mode`, континент визуально "притянут" к позвоночнику.

    *   **Валидация схемы данных:**
        *   Выходной объект `ContinentData` имеет все необходимые поля (`mask`, `heightmap`, `center` и т.д.).
        *   Типы данных в объекте корректны (`mask` — это `np.ndarray` типа `bool`, `center` — `tuple(int, int)` и т.д.). Эти данные должны быть готовы к передаче в следующий пакет.

### Рабочий пакет 2: Ключевая анатомия и рельеф

Здесь мир обретает трехмерность, скелет и внутреннюю "кровеносную" систему. Это самый важный этап для проверки новой логики v3.0.

*   **Состав:**
    *   Phase 2: Skeleton Generation
    *   Phase 3: Vessel Network Generation

*   **Цель:** Сгенерировать финальный рельеф, основанный на костной структуре, и проложить по нему сосудистую сеть, которая реалистично огибает кости.

*   **Выходной артефакт:**
    1.  **Визуализация:** Набор из трех ключевых изображений для сравнения:
        *   Карта плотности костей (`bone_density_map`) в градациях серого (кости — белые).
        *   Итоговая карта высот (`elevation`) в градациях серого (горы — белые).
        *   Карта плотности костей с наложенной поверх нее сетью сосудов (`vessels`).
    2.  **Данные:** `elevation_map`, `bone_density_map`, `skeleton_structure`, `vessels`, `vein_outlets`.

*   **Критерии валидации:**

    *   **Функциональная валидация:**
        *   Позвонки размещаются вдоль "позвоночника" с заданным интервалом.
        *   L-система для рёбер генерирует ветвящуюся структуру без ошибок.
        *   Тест `test_density_aware_pathfinding` **(критически важен!)**: на искусственной карте с "костяной стеной" путь сосуда должен гарантированно идти в обход, а не напролом.
        *   Алгоритм колонизации пространства успешно соединяет все органы.

    *   **Визуальная валидация:**
        *   На карте высот (`elevation`) четко прослеживаются возвышенности, соответствующие позвоночнику и рёбрам с карты `bone_density_map`.
        *   **Самая главная проверка:** На совмещенном изображении сосуды должны явно "избегать" белых (плотных) зон на карте костей. Они должны проходить по "мягким тканям".
        *   Точки `vein_outlets` расположены в низинах и на артериях.

    *   **Валидация схемы данных:**
        *   `elevation` и `bone_density_map` — это массивы `np.ndarray` 512x512 типа `float`.
        *   `vessels` — это список словарей, каждый из которых содержит `waypoints` (путевые точки), доказывающие обходной маршрут.
        *   `vein_outlets` — это список словарей с `position` и `strength`.

### Рабочий пакет 3: Системы жизнеобеспечения (Гидрология и Климат)

На этом этапе "статичная" анатомия оживает: по ней текут реки и формируется климат.

*   **Состав:**
    *   Phase 4: Hydrology
    *   Phase 4.5: Hydraulic Erosion
    *   Phase 5: Climate

*   **Цель:** Создать реалистичную гидрологическую сеть, сформировать речные долины через эрозию и рассчитать карты климата.

*   **Выходной артефакт:**
    1.  **Визуализация:**
        *   Эродированная карта высот с наложенной синей маской рек.
        *   Карта температуры (в виде "тепловой карты", от синего к красному).
        *   Карта влажности (в виде "тепловой карты", от желтого к синему).
    2.  **Данные:** `eroded_elevation`, `river_mask`, `temperature`, `moisture`.

*   **Критерии валидации:**

    *   **Функциональная валидация:**
        *   Алгоритм D8 корректно направляет поток "вниз" на тестовом уклоне.
        *   Проверка на отсутствие "стоков" (sinks) или их корректную обработку.
        *   Тест `test_bone_protection` подтверждает, что эрозия на костях слабее.
        *   Источники рек (`water_sources`) включают все `vein_outlets` из предыдущего пакета.

    *   **Визуальная валидация:**
        *   Реки текут из высокогорных районов (или `vein_outlets`) в низины и, в конечном итоге, впадают в "океан". Речная сеть выглядит древовидно.
        *   Вдоль рек на эродированной карте высот должны быть видны четкие долины/каньоны.
        *   Карта температуры: горячо у `metabolic_core`, холодно в горах.
        *   Карта влажности: влажно вдоль рек и в низинах, сухо в горах.

    *   **Валидация схемы данных:**
        *   Все выходные карты — это массивы `np.ndarray` 512x512 типа `float` в диапазоне.

### Рабочий пакет 4: Финальная детализация и классификация

Финальный штрих — заселение мира "живыми" тканями и системами на основе всех собранных ранее данных.

*   **Состав:**
    *   Phase 6: Respiration System
    *   Phase 7: Tissues (Biome Assignment)

*   **Цель:** Классифицировать каждую клетку мира, присвоив ей тип ткани (биом) на основе сложного набора правил и всех предыдущих карт.

*   **Выходной артефакт:**
    1.  **Визуализация:**
        *   Карта `bioactive_saturation` ("тепловая карта", показывающая "облака" выдоха).
        *   Итоговая, полноцветная карта мира (`tissue_map`), где каждый цвет соответствует определенному типу ткани/биому.
    2.  **Данные:** `caverns`, `bioactive_saturation`, `tissue_map`.

*   **Критерии валидации:**

    *   **Функциональная валидация:**
        *   Каверны располагаются преимущественно в зонах с высоким "потенциалом" (у костей, в грудном регионе).
        *   Алгоритм BFS для "выдоха" корректно распространяет и ослабляет сигнал.
        *   Набор тестовых "контекстов" для клеток корректно классифицируется системой правил из `tissue_rules.yaml`.

    *   **Визуальная валидация:**
        *   На карте `bioactive_saturation` "облака" исходят из каверн.
        *   Финальная карта тканей выглядит логично: `chitinous_plates` на костяных хребтах, `acid_lake` у желудка, `spore_fields` в зонах высокой биоактивности, `lymph_river` совпадает с маской рек.
        *   Нет больших "неклассифицированных" областей.

    *   **Валидация схемы данных:**
        *   `tissue_map` — это массив `np.ndarray` 512x512 со строковыми идентификаторами тканей.

### Сильные стороны архитектуры (Почему она масштабируема)

1.  **Модульность и разделение ответственности:** Каждая фаза — это, по сути, отдельный "модуль" с четкими входными и выходными данными. Вы можете:
    *   **Изменить логику внутри фазы:** Например, полностью заменить L-системы для генерации рёбер на другой алгоритм. Пока на выходе будет `bone_density_map` и `skeleton_structure`, остальная система этого "не заметит".
    *   **Вставить новую фазу:** Вы можете легко добавить `Phase 1.5: Major Features` между `Phase 1` и `Phase 2` для создания, например, гигантского горного хребта или разлома.
    *   **Отключить фазу:** Если вам не нужна, скажем, гидравлическая эрозия, вы можете просто пропустить `Phase 4.5` и передать `elevation` из `Phase 2` напрямую в `Phase 5`.

2.  **Управление через конфигурацию:** Многие параметры вынесены в YAML-файлы. Вы можете кардинально изменить мир, не трогая код, просто меняя `sea_level`, `perlin_scale`, `bone_density_penalty` и т.д. Это "мягкий" способ масштабирования.

3.  **Детерминированный Seed-менеджмент:** Благодаря `_hash_seed`, вы можете добавить новую фичу со своим уникальным суффиксом (например, `_hash_seed(seed, "peninsula")`). Это гарантирует, что ваша новая фича будет детерминированной, но при этом **не изменит результаты** всех предыдущих и не связанных с ней фаз. Это критически важно для тестирования и отладки.

### Ограничения и вызовы для масштабирования

1.  **Производительность:** Текущий план содержит циклы `for x in ... for y in ...`. На карте 512x512 это работает приемлемо. На карте 2048x2048 это будет невыносимо медленно. **Масштабирование разрешения карты потребует обязательной векторизации кода с использованием NumPy.** Операции должны выполняться над целыми массивами, а не над отдельными клетками.

2.  **Однонаправленный поток данных:** Система работает как водопад: данные текут только "вниз". Если вам понадобится, чтобы поздний этап повлиял на ранний (например, "тип ткани из Phase 7 должен влиять на высоту рельефа из Phase 2"), это потребует значительного усложнения архитектуры — введения **циклов обратной связи** и, возможно, нескольких проходов генерации.

3.  **Неявные предположения:** Текущий алгоритм неявно предполагает наличие **одной основной массы суши**. Расчет центра масс, главной оси, размещение позвоночника — все это ориентировано на единый континент. Ваша идея с островом напрямую бросает вызов этому предположению.

### Практическое руководство: Как реализовать ваши идеи

Давайте разберем, как добавить предложенные вами фичи в существующую архитектуру.

#### Пример 1: "От континента всегда будет тянуться полуостров-рука"

Это идеальный пример для демонстрации мощи модульного подхода.

*   **Где вносить изменения:** Лучшее место — **сразу после `Phase 1b: Continent Growth`**. Можно создать новую `Phase 1c: Peninsula Generation`.

*   **Пошаговый план реализации:**
    1.  **Входные данные:** Принять на вход готовую `continent_mask` из `Phase 1b`.
    2.  **Найти точку старта:** Найти самую "крайнюю" точку на береговой линии континента (например, самую западную или восточную). Это будет "плечо".
    3.  **Сгенерировать путь "руки":** Используя ту же логику, что и в `Phase 1a: Spine Creation`, сгенерировать искривленный путь (через 1D Perlin Noise), начинающийся от "плеча" и уходящий в океан.
    4.  **Создать маску влияния:** Создать вокруг этого пути поле влияния, которое плавно затухает с расстоянием.
    5.  **Сформировать маску полуострова:** Применить порог к маске влияния, чтобы получить бинарную маску новой суши.
    6.  **Объединить:** Добавить новую маску к основной маске континента (`final_mask = continent_mask | peninsula_mask`).
    7.  **Сгладить соединение:** Применить легкий `gaussian_filter` к объединенной маске, чтобы сгладить место соединения полуострова с континентом.
    8.  **Выходные данные:** Передать обновленную `continent_mask` в `Phase 2`.

*   **Анализ влияния:** Это изменение **идеально изолировано**. Все последующие фазы (Скелет, Сосуды, Реки) просто будут работать с континентом новой, более сложной формы, им не нужно знать, *как* он был создан.

#### Пример 2: "Всегда будет в океане 1 крупный остров"

Эта задача сложнее, так как она нарушает предположение о "едином континенте".

*   **Где вносить изменения:** Внутри `Phase 1b: Continent Growth`, на этапе работы с `heightmap`.

*   **Пошаговый план реализации (Метод "Подталкивания высот"):**
    1.  **Сгенерировать базовый `heightmap`:** Как и раньше, с помощью шума Перлина.
    2.  **Найти место для острова:** Определить область в "океане", вдали от потенциального центра основного континента.
    3.  **Создать "купол высоты":** Сгенерировать 2D Гауссов "пузырь" (или использовать другой шум) в выбранной области. Этот "пузырь" будет представлять собой плавное поднятие рельефа.
    4.  **Добавить к карте высот:** Сложить базовый `heightmap` и "купол высоты". Это создаст область с искусственно завышенным рельефом.
    5.  **Применить порог `sea_level`:** Как и раньше. Теперь, помимо основного континента, над уровнем моря поднимется и ваш остров.

*   **Анализ влияния (здесь всё сложнее):**
    *   **Критически важная доработка:** Код в `Phase 1b`, который рассчитывает геометрию (`center_of_mass`, `major_axis`) и размещает органы, **сломается или будет работать некорректно**. Его нужно будет модифицировать:
        1.  **Идентификация островов:** После создания маски суши нужно использовать функцию вроде `scipy.ndimage.label` для поиска всех несвязанных участков суши.
        2.  **Выбор основного континента:** Найти самый большой участок по площади.
        3.  **Применение логики:** Выполнять расчет центра масс, главной оси, размещение органов и привязку позвоночника **только для самого большого участка**.
    *   **Влияние на другие фазы:** Большинство последующих фаз (Эрозия, Климат, Ткани) будут работать корректно, так как они оперируют данными на уровне клеток и им не важно, связана ли эта клетка с материком.

### Вывод

Текущая работа **определенно масштабируема**. Её архитектура позволяет как вносить тонкие изменения через конфигурацию, так и добавлять крупные новые фичи через создание новых фаз.

Ключ к успешному масштабированию — это **строгое соблюдение "контрактов" между фазами** (формат входных и выходных данных) и **осознанная доработка последующих фаз**, если новая фича меняет фундаментальные предположения (как в примере с островом).
