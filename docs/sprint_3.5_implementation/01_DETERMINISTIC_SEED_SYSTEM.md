# 01. Система детерминированного seed

## Что это?

**Детерминированная генерация** - это подход, при котором один и тот же входной параметр (seed) всегда производит абсолютно одинаковый результат.

```
seed "forest_world" → ВСЕГДА → одна и та же карта
seed "desert_realm" → ВСЕГДА → другая, но тоже стабильная карта
```

## Зачем это нужно?

### Преимущества:
1. **Воспроизводимость** - можно поделиться seed с другими игроками
2. **Отладка** - баги воспроизводятся стабильно
3. **Тестирование** - unit tests дают предсказуемые результаты
4. **Multiplayer** - все клиенты генерируют одинаковый мир

### Проблемы без детерминизма:
```python
# ❌ ПЛОХО: Каждый раз разный результат
import random
random.random()  # 0.3421
random.random()  # 0.8901 (другое значение!)
```

## Как это работает?

### Шаг 1: Хеширование seed

Используем **hashlib.sha256()** для преобразования строки в число:

```python
import hashlib

def _hash_seed(self, seed: str) -> int:
    """
    Преобразует строковый seed в 64-битное целое число.

    Почему SHA-256?
    - Детерминированный (одна строка → одно число)
    - Равномерное распределение
    - Необратимый (число → строка невозможно)
    """
    hash_bytes = hashlib.sha256(seed.encode('utf-8')).digest()

    # Берём первые 8 байт (64 бита) и преобразуем в int
    seed_int = int.from_bytes(hash_bytes[:8], 'big')

    # Ограничиваем до 2^63-1 (максимум для signed int64)
    return seed_int & 0x7FFFFFFFFFFFFFFF
```

**Пример:**
```python
_hash_seed("forest") → 5234892304892304823
_hash_seed("forest") → 5234892304892304823  # ВСЕГДА одинаково!
_hash_seed("desert") → 9823749823749283749  # Другое число
```

### Шаг 2: Инициализация RNG

Используем полученное число для инициализации **NumPy RNG**:

```python
import numpy as np

class WorldGenerator:
    def __init__(self, seed: str):
        self.seed_string = seed
        self.seed_int = self._hash_seed(seed)

        # Создаём генератор случайных чисел
        self.rng = np.random.default_rng(self.seed_int)
```

**Почему NumPy?**
- `random.Random()` не гарантирует одинаковое поведение между версиями Python
- `np.random.default_rng()` стабилен и быстр
- Поддерживает vectorized операции (генерация массивов)

### Шаг 3: Использование RNG

Все случайные операции используют `self.rng`:

```python
def generate(self):
    # ❌ ПЛОХО: Не детерминировано
    value = random.random()

    # ✅ ХОРОШО: Всегда одинаково для данного seed
    value = self.rng.random()

    # Генерация массивов:
    noise = self.rng.random((256, 256))  # Всегда одинаковый шум
```

## Полная схема работы

```
┌─────────────┐
│ seed: str   │  Пользователь вводит: "my_world"
└──────┬──────┘
       │
       ▼
┌─────────────────────┐
│ hashlib.sha256()    │  "my_world" → [bytes array]
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│ int.from_bytes()    │  [bytes] → 7234892304892304823
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│ np.random.         │  Инициализация RNG
│ default_rng(seed)   │
└──────┬──────────────┘
       │
       ▼
┌─────────────────────┐
│ rng.random()        │  Генерация: шум, точки, числа
│ rng.integers()      │  Всегда одинаково для seed!
│ rng.choice()        │
└─────────────────────┘
```

## Валидация детерминизма

### Unit Test:

```python
def test_seed_deterministic():
    """Один seed → всегда одинаковый результат"""
    gen1 = WorldGenerator("test_seed")
    gen2 = WorldGenerator("test_seed")

    map1 = gen1.generate()
    map2 = gen2.generate()

    # Проверяем идентичность
    assert map1.sectors == map2.sectors
    assert np.array_equal(map1.elevation, map2.elevation)
```

### Ручная проверка:

```python
gen = WorldGenerator("forest")
gen.generate()

gen2 = WorldGenerator("forest")
gen2.generate()

```

## Важные замечания

### ✅ Что делать:
1. Всегда использовать `self.rng` для генерации
2. Передавать seed в дочерние функции через RNG
3. Избегать внешних источников случайности

### ❌ Чего НЕ делать:
1. Использовать `random.random()` напрямую
2. Использовать `time.time()` для генерации
3. Читать внешние файлы без фиксированного seed
4. Полагаться на порядок итерации `dict` (в Python 3.7+ это OK, но осторожно)

### Подводные камни:

**Проблема: Порядок генерации имеет значение**
```python
# ❌ ПЛОХО: Порядок меняет результат
def generate(self):
    self._generate_rivers()  # Вызов 1
    self._generate_mountains()  # Вызов 2

# Если поменять местами:
def generate(self):
    self._generate_mountains()  # Вызов 1 (другой random!)
    self._generate_rivers()  # Вызов 2
    # Результат будет ДРУГИМ!
```

**Решение:** Зафиксировать порядок вызовов и следовать ему всегда.
