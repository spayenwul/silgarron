## 1. Poisson Disk Sampling для размещения каверн

### Предложение
Заменить жадный алгоритм в `_select_distributed_points` на Poisson Disk Sampling для более естественного и равномерного распределения альвеолярных каверн.

### Мой анализ
**Вердикт: ✅ ПОЛНОСТЬЮ СОГЛАСЕН**

**Обоснование:**
- Жадный алгоритм может создавать **предсказуемые паттерны** (точки выстраиваются в линию или сетку)
- Для **биологических структур** (лёгкие мира) важна органичность размещения
- Poisson Disk Sampling гарантирует:
  - Минимальное расстояние между точками
  - Отсутствие кластеризации
  - Визуально более естественное распределение
- Алгоритм Bridson хорошо изучен и эффективен

**Что сделано:**
1. ✅ Добавлена функция `_poisson_disk_sampling()` с полной реализацией
2. ✅ Оставлен жадный алгоритм как `_greedy_distributed_selection()` для совместимости
3. ✅ Добавлен конфиг-параметр `cavern_placement_method: "poisson" | "greedy"`
4. ✅ Poisson стал методом по умолчанию (более органичный)
5. ✅ Добавлены ссылки на материалы Bridson в раздел "Материалы для изучения"

**Преимущества интеграции:**
- Более органичное размещение каверн
- Гибкость (можно переключить на greedy для отладки)
- Соответствует биопанк-эстетике

## 2. Система "очков соответствия" для тканей

### Предложение
Заменить цепочку if/elif и приоритеты на систему начисления очков, где каждое правило добавляет/вычитает баллы за попадание в диапазон. Ткань с максимальными очками побеждает.

### Мой анализ
**Вердикт: 🟡 ЧАСТИЧНО СОГЛАСЕН (с уточнением)**

**Обоснование:**

**За систему очков:**
- Позволяет создавать **более плавные переходы** между тканями
- Более гибкая для сложных комбинаций параметров
- Попадание в "центр диапазона" может давать больше очков (weight по расстоянию)

**Против немедленной реализации:**
- Для Sprint 3.5 это **overengineering** (избыточная сложность)
- Текущая система приоритетов **проще для понимания** новых разработчиков
- Система очков требует **дополнительного тюнинга** весов (ещё больше "магических чисел")
- Можно добавить позже без ломающих изменений

**Что сделано:**
1. ✅ Оставлена текущая система приоритетов для Sprint 3.5
2. ✅ Добавлен **TODO-комментарий** в `_select_tissue()` с:
   - Описанием будущей системы очков
   - Примером реализации (distance_from_center)
   - Указанием на Sprint 4+ как целевую фазу
3. ✅ Задокументировано обоснование ("простота для первой итерации")

**Рациональ решения:**
- Sprint 3.5 уже достаточно амбициозный (48-55 часов)
- Приоритетная система работает для первой итерации
- Систему очков легче оценить **после визуализации** результатов текущей системы
- Это хороший кандидат на рефакторинг в Sprint 4

## 3. Итеративный тюнинг параметров

### Предложение
Создать явную задачу на тюнинг "магических чисел" (lymph_threshold = 50, airflow_decay_rate = 0.95, веса шумов) с итеративной визуализацией. Время: 2-3 часа.

### Мой анализ
**Вердикт: ✅ АБСОЛЮТНО СОГЛАСЕН - ЭТО КРИТИЧНО**

**Обоснование:**
- "Магические числа" - **самая большая проблема** текущего плана
- Без тюнинга карта будет выглядеть **неправильно** (главный риск проекта)
- Невозможно подобрать правильные значения "на глаз" без итераций
- **2-3 часа недостаточно** - реально нужно 4-5 часов для качественного результата

**Что сделано:**
1. ✅ Создана **Задача 5.3: Итеративный тюнинг анатомических параметров** (4-5 часов)
2. ✅ Выделены **все ключевые параметры** по категориям:
   - Скелетная структура (5 параметров)
   - Лимфатическая система (2 параметра)
   - Дыхательная система (4 параметра)
   - Метаболическое тепло (3 параметра)
   - Perlin noise (4 параметра)
3. ✅ Разработана **методология тюнинга**:
   - Скрипт `tune_parameters.py` для автоматизации
   - 5 метрик визуальной валидации (по одной на каждый слой сканирования)
   - Пошаговый процесс (5 шагов, каждый 0.5-1.5 часа)
4. ✅ Определены **критерии завершения**:
   - Все 5 слоёв выглядят "биологично"
   - Одобрение команды лора
   - Все биологические тесты проходят
   - Создан отчёт с примерами до/после
5. ✅ Добавлены **инструменты** для ускорения:
   - CLI команды для генерации с визуализацией
   - Автоматический тюнинг по диапазону
   - Сравнение нескольких конфигураций

**Влияние на спринт:**
- Время Фазы 5: 8-10 часов → **12-15 часов**
- Общее время: 44-50 часов → **48-55 часов**
- Риск "недостаточной биологичности": Высокий → **Низкий**
- Риск "искусственного хребта": Высокий → **Средний**

**Почему это критично:**
- Без тюнинга мы получим **технически правильную**, но **визуально неубедительную** карту
- Биопанк-эстетика **требует** органичности
- Команда лора должна **одобрить** визуал, иначе вся работа бессмысленна
- Это **инвестиция в качество**, а не бюрократия
