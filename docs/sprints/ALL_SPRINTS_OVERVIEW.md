## 🎯 SPRINT 3: World Generation Refactoring

**Период:** 2-16 ноября (14 дней)  
**Время:** 40 часов  
**Приоритет:** 🟡 Высокий  
**Статус:** ⏳ Запланировано

### Цель
Улучшить процедурную генерацию мира на основе тегов и совместимости

### Ключевые Задачи

#### 3.1 Система Тегов (8ч)
- Дополнить `data/tags_registry.yaml`
- Создать `services/tag_service.py`
- Валидация тегов при загрузке YAML
- Тесты

#### 3.2 Compatibility Service (10ч)
- Создать `services/compatibility_service.py`
- Алгоритм подсчёта совместимости
- Формула: `score = Σ(weight * tag_match)`
- Обработка несовместимостей
- Тесты

#### 3.3 Обновить Генераторы (15ч)
- Рефакторинг `SpatialLocationGenerator`
- Использовать совместимость вместо случайности
- Создать систему "паспортов" локаций
- Генерация биомов на основе тегов
- Интеграция с Noise Maps

#### 3.4 Тестирование Генерации (5ч)
- Генерация 100 регионов
- Проверка разнообразия
- Валидация: враждебные расы не соседствуют
- Performance: генерация региона < 2 сек

#### 3.5 Документация (2ч)
- Обновить `generators/README.md`
- Создать ADR-009: Tag-Based Generation

### Deliverables
- ✅ TagService работает
- ✅ CompatibilityService подсчитывает совместимость
- ✅ Генераторы используют теги
- ✅ Система паспортов локаций
- ✅ Логичный, разнообразный мир

### Dependencies
- Нет (параллельно Sprint 1-2)

### Risks
- ⚠️ Сложность балансировки весов совместимости
- ⚠️ Performance генерации больших регионов

**Детальный план:** Создать `docs/sprints/SPRINT_3_PLAN.md`

## 🎯 SPRINT 4: Physics Integration

**Период:** 17 ноября - 15 декабря (28 дней)  
**Время:** 60 часов  
**Приоритет:** 🔴 Критический (но БЛОКИРОВАН)  
**Статус:** ⏳ Ожидает команду физики

### Цель
Заменить заглушки физической симуляции реальными расчётами

### Ключевые Задачи

#### 4.1 Интеграция PhysicalSimulator (15ч)
- Заменить заглушку в `combat/physical_simulator.py`
- Интеграция с библиотекой физики (от другой команды)
- API для расчётов:
  - Траектория снарядов
  - Столкновения
  - Повреждение материалов
- Тесты точности

#### 4.2 BodySystem - Реальная Физиология (20ч)
- Заполнить `combat/body_system.py` логикой
- Реалистичная кровопотеря (давление, объём)
- Система шока (болевой, травматический)
- Влияние ран на функциональность
- Взаимодействие между ранами
- Анатомические особенности рас

#### 4.3 Material Properties (10ч)
- Создать `data/materials.yaml`
- Свойства: прочность, вес, твёрдость, упругость
- Интеграция с `models/item.py`
- Расчёт проникновения/повреждения

#### 4.4 Валидация и Рефери (10ч)
- Physics Referee (проверка адекватности LLM)
- Автотесты граничных случаев
- Валидация: сила < max_strength
- Валидация: вес соответствует материалу

#### 4.5 Документация (5ч)
- Обновить `combat/README.md`
- Создать ADR-010: Physics Implementation

### Deliverables
- ✅ PhysicalSimulator использует реальную физику
- ✅ BodySystem симулирует физиологию
- ✅ Материалы влияют на взаимодействия
- ✅ Physics Referee проверяет LLM
- ✅ Реалистичная боевая система

### Dependencies
- Sprint 2 завершён (Function Calling нужен)
- **БЛОКЕР:** Команда физики предоставит библиотеку

### Risks
- 🔴 **КРИТИЧЕСКИЙ:** Зависимость от другой команды
- ⚠️ Сложность интеграции сторонней библиотеки
- ⚠️ Баланс: реализм vs играбельность

**Детальный план:** Создать `docs/sprints/SPRINT_4_PLAN.md`

## 🎯 SPRINT 6: World Simulation (Macro/Meso/Micro)

**Период:** 11 января - 28 февраля (7 недель)  
**Время:** 70 часов  
**Приоритет:** 🟢 Средний  
**Статус:** ⏳ Запланировано

### Цель
Реализовать трёхуровневую симуляцию живого мира

### Ключевые Задачи

#### 6.1 Time Manager (8ч)
- Создать `core/time_manager.py`
- Управление ходами (turn-based)
- События через N ходов
- День/ночь цикл
- Сезоны (влияние на мир)

#### 6.2 Level 3: Micro Simulation (20ч)
- Симуляция внутри локации
- NPC поведение (AI agents)
- Предметы (порча, ржавчина)
- Ресурсы (восстановление)
- Погода (локальные эффекты)

**Примеры:**
- Торговец перемещается по городу
- Пища портится в инвентаре
- Трава растёт на поле боя
- Раны заживают со временем

#### 6.3 Level 2: Meso Simulation (25ч)
- Миграции рас между регионами
- Торговые пути
- Распространение слухов/информации
- Изменение популяций (рост/убыль)
- Экологические изменения

**Примеры:**
- Караван движется между городами
- Цены меняются в зависимости от доступности
- Монстры мигрируют зимой
- Болезнь распространяется между поселениями

#### 6.4 Level 1: Macro Simulation (15ч)
- Континентальные события
- Войны между фракциями
- Эпидемии
- Природные катастрофы
- Глобальные квесты

**Примеры:**
- Война между расами
- Извержение вулкана влияет на регионы
- Эпидемия охватывает континент
- Падение метеорита создаёт новый биом

#### 6.5 Event Sourcing Integration (7ч)
- События симуляции → EventStore
- Возможность "отмотать" время
- Анализ истории мира

#### 6.6 Тестирование и Документация (5ч)
- Тесты каждого уровня симуляции
- Performance (1000 ходов за <1 сек)
- Создать `simulation/README.md`
- Создать ADR-012: World Simulation Design

### Deliverables
- ✅ TimeManager управляет временем
- ✅ 3 уровня симуляции работают
- ✅ Мир "живёт" независимо от игрока
- ✅ События влияют друг на друга
- ✅ Emergent gameplay возможен

### Dependencies
- Sprint 3 завершён (генерация мира нужна)

### Risks
- ⚠️ Сложность балансировки скорости симуляции
- ⚠️ Performance при большом количестве событий
- ⚠️ Баланс: симуляция vs gameplay

**Детальный план:** Создать `docs/sprints/SPRINT_6_PLAN.md`

Sprint 1 (12ч) → Sprint 2 (30ч) → Sprint 4 (60ч) → Sprint 5 (45ч) → Sprint 7
                                        ↑

## 📝 Рекомендации

### Для Solo Developer

**Стратегия 1: Последовательно**
```
Sprint 1 → Sprint 2 → Sprint 3 → [ждём физику] → Sprint 4 → Sprint 5 → Sprint 6 → Sprint 7
```
**Плюсы:** Фокус на одной задаче  
**Минусы:** Долгое ожидание физики блокирует всё

---

**Стратегия 2: Параллельная работа (рекомендуется)**
```
Week 1-2:   Sprint 1
Week 3-4:   Sprint 2
Week 5-7:   Sprint 3
Week 8-11:  [Ожидание физики → работа над Sprint 6 части 6.1-6.3]
Week 12-15: Sprint 4 (когда физика готова)
Week 16-18: Sprint 5
Week 19-22: Завершение Sprint 6
Week 23+:   Sprint 7 (ongoing)
```
**Плюсы:** Не теряем время в ожидании  
**Минусы:** Переключение контекста

---

**Разделение ролей:**
- **Backend Dev:** Sprint 1, 2, 4, 6

- **Physics Team:** Sprint 4 (параллельно 1-3)
- **World Designer:** Sprint 3, 6

### Scope Creep Protection

Правила защиты от расползания scope:

1. **Новая фича → в BACKLOG, не в текущий спринт**
2. **Одна фича убрана → одна фича добавлена**
3. **Nice-to-have → Sprint 7, не раньше**

### Technical Debt Management

После каждого спринта:
- Выделить 10% времени на рефакторинг
- Исправить 2-3 "TODO" из кода
- Обновить устаревшие зависимости
