## Executive Summary

Анализ baseline snapshot выявил **критические проблемы** в текущей мультипликативной системе:

🔴 **КРИТИЧНО:** Экстремальные значения scores (до 648!)
🔴 **КРИТИЧНО:** Неконтролируемая специализация рас (std до 90.61)
🟡 **ПРЕДУПРЕЖДЕНИЕ:** Низкая вариативность совместимости биомов (std < 0.5)
🟢 **ОК:** Forbidden combinations работают (11.4% запретов)

**Вердикт:** Система нуждается в немедленном рефакторинге. Гибридная формула обязательна.

## График 1: Compatibility Distribution

### Метрики

```
Mean:     1.00 (нейтральный)
Median:   1.00
Std:      0.43 (НИЗКАЯ вариативность)
Samples:  1225 (50 биомов → 50*49/2 = 1225 пар)
Forbidden: 140 (11.4%)
```

### Интерпретация

#### 🟡 Проблема 1: Низкая вариативность (std = 0.43)

**Что это значит:**
Большинство биомов имеют score около 1.0 (нейтральный). Система **не создаёт достаточного контраста** между совместимыми и несовместимыми биомами.

**Почему это плохо:**
- Все биомы "одинаково серые"
- Нет ярко выраженных синергий (score > 2.0)
- Нет мягких конфликтов (0.2 < score < 0.8)
- Только бинарность: либо 1.0 (норм), либо 0.0 (forbidden)

**Ожидаемое значение для хорошей системы:**
`std >= 0.5` (желательно 0.6-0.8)

**Причина:**
Глобальные синергии и конфликты из `tags_registry.yaml` либо слишком слабые, либо их мало.

**Решение:**
Гибридная формула с `base_affinity` позволит создать более выраженные различия.

---

#### 🟢 Хорошо: Forbidden combinations работают

**Что это значит:**
11.4% (140 из 1225) пар биомов имеют score = 0.0, что соответствует `forbidden_combinations`.

**Почему это хорошо:**
Жёсткие запреты (например, `terrain:aquatic + terrain:subterranean`) корректно применяются.

**Что сохранить:**
В гибридной формуле forbidden_combinations должны остаться как есть (приоритет #1).

---

#### 🔍 Наблюдение: Mean = 1.0 (нейтральный)

**Что это значит:**
В среднем биомы нейтрально совместимы друг с другом.

**Это нормально?**
Да, для **биом-биом** совместимости. Большинство биомов должны мирно сосуществовать, с редкими исключениями (forbidden).

**Что изменится в гибридной формуле:**
Ничего. Mean останется ~1.0, но **разброс (std) увеличится**.

### Интерпретация

#### 🔴 КРИТИЧЕСКАЯ ПРОБЛЕМА: Экстремальные значения

**fen-kin: score до 648!**

Это **абсурдно высокое** значение. Для сравнения:
- Нейтральный score: 1.0
- Хороший score: 2.0-3.0
- Отличный score: 4.0-5.0
- **fen-kin в идеальном биоме: 648!**

**Почему это произошло:**
Мультипликативная система с большим количеством модификаторов:
```python
# Гипотетический расчёт для fen-kin
score = 1.0
score *= 3.0  # ecology:toxic
score *= 2.0  # surface:unstable
score *= 1.8  # ecology:fertile (если инвертированный)
score *= 1.5  # danger:environmental
score *= 2.0  # resource:pure_lymph
score *= 1.5  # manifestation:high
score *= 2.0  # еще какой-то тег
score *= 1.5  # и еще один...
# Итог: 1.0 * 3 * 2 * 1.8 * 1.5 * 2 * 1.5 * 2 * 1.5 = 364.5
# А если биом имеет 12+ тегов → 648!
```

**Почему это плохо:**
1. **Неконтролируемость:** Невозможно предсказать итоговый score
2. **Хрупкость:** Изменение одного коэффициента с 2.0 на 1.5 → score 648 → 243 (в 2.6 раза!)
3. **Несбалансированность:** Одни расы имеют score 1-3, другие 600+
4. **Невозможность расширения:** Добавление нового тега → непредсказуемый рост

**Решение:**
Гибридная формула с границами `[0.0, 5.0]` предотвратит такие выбросы.

---

#### 🔴 КРИТИЧНО: Все расы - строгие специалисты

**Что это значит:**
У всех 10 рас `std > 3.0`, что означает **экстремальную специализацию**.

**Классификация:**
- `std < 0.3` → Универсал
- `0.3 < std < 0.6` → Умеренный специалист
- `std > 0.6` → Строгий специалист
- **std > 10.0** → 🔴 Экстремальный специалист (это ненормально!)

**Проблема:**
Специализация - это хорошо, НО:
- `ursines` имеют range [0, 2.93] → еле выживают в лучшем биоме (score=2.93)
- `fen-kin` имеют range [0, 648] → в одном биоме боги, в другом 0

**Почему это плохо для геймплея:**
1. Расы не могут мигрировать (score=0 в большинстве биомов)
2. Невозможно создать многорасовые регионы
3. Игрок не может выбрать расу без привязки к конкретному биому

**Ожидаемое значение:**
- 3-4 расы: `0.3 < std < 0.6` (умеренные специалисты)
- 3-4 расы: `std > 0.6` (строгие специалисты)
- 2-3 расы: `std < 0.3` (универсалы)

**Решение:**
Гибридная формула позволит:
- Сохранить специализацию через `multipliers`
- Дать минимальную выживаемость через `base_affinity`
- Контролировать разброс через границы

---

#### 🔍 Наблюдение: Low Mean для большинства рас

**Что это значит:**
Средний score для большинства рас < 10, что говорит о том, что они **плохо совместимы** с большинством биомов.

**Почему это произошло:**
Мультипликативная система с большим количеством штрафных модификаторов (< 1.0).

**Это нормально?**
Нет. Даже специалисты должны иметь mean > 1.0 (хотя бы нейтральная совместимость).

**Решение:**
В гибридной формуле `base_score = 1.0` гарантирует, что mean не уйдёт ниже нейтрального.

## Выявленные проблемы (приоритизированный список)

### 🔴 Критические (блокируют релиз)

1. **Экстремальные значения scores (до 648)**
   - Причина: Мультипликативная система без границ
   - Решение: Гибридная формула с clamp [0.0, 5.0]
   - Приоритет: P0 (самое важное)

2. **Неконтролируемая специализация рас**
   - Причина: Чрезмерное умножение модификаторов
   - Решение: Сегментация на base_affinity + multipliers
   - Приоритет: P0

3. **Невозможность балансировки**
   - Причина: Изменение одного коэффициента → непредсказуемый каскад
   - Решение: Аддитивная часть (base_affinity) для предсказуемости
   - Приоритет: P0

### 🟡 Важные (нужно исправить)

4. **Низкая вариативность биом-биом совместимости (std=0.43)**
   - Причина: Слабые синергии/конфликты в tags_registry
   - Решение: После внедрения гибридной формулы добавить больше правил
   - Приоритет: P1

5. **Низкий mean для большинства рас (<10)**
   - Причина: Много штрафных модификаторов
   - Решение: Гибридная формула гарантирует base_score=1.0
   - Приоритет: P1

### 🟢 Желательные (можно отложить)

6. **Отсутствие рас-универсалов**
   - Причина: Все расы имеют высокий std
   - Решение: После внедрения формулы создать 2-3 расы с low std
   - Приоритет: P2

7. **Нет данных о реальной генерации**
   - Причина: SpatialLocationGenerator не реализован
   - Решение: Реализовать генератор (отдельный спринт)
   - Приоритет: P2

**Метрика успеха:** Линейная зависимость mean от суммы base_affinity
